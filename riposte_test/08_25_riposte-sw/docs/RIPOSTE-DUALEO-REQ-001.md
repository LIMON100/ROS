## 2. 현행 아키텍처 대비 요약

현행(SEEKER-SDD-001 v1.8, 코드 기준 2026-08-12):

- **단일 EO 카메라** 파이프라인: V4L2 mmap 캡처(구현 완료) → Hailo 추론(**스켈레톤**, INTEGRATE 마커 상태) → 다중대상 Tracker(탐욕 연관 + α-β, sticky primary) → 단안 TargetEstimator → TrackBus(shm SeqSlot).
- 검출기 입력은 **전체 프레임 1회 추론** 전제. 타일링·리사이즈 전략 없음.
- IR 2번 채널은 **녹화 전용**이며 인지 융합에 쓰이지 않음.
- 확인 게이팅은 `MIN_TRACK_HITS=2` (연속 2회 연관) — R-6의 "5프레임 중 4회" 슬라이딩 윈도우와 다름.
- primary 선정: 품질(quality) 최고 + sticky. R-8의 "최대 크기 우선"과 다름.
- TrackState에 대상 개수·클래스·출처 카메라 필드 없음.
- OBC: GCS TARGET 명령(`MissionTarget`, NED 좌표+헤딩)을 받아 큐 지점으로 항법하는 경로는 존재(MissionSource). 속도 기반 예상 접근점(lead) 산출은 없음.
- 지오펜스: 홈 기준 **반경 150 m + 고도 밴드**(SM-3, 위반 시 disengage). 사각형 GPS 폴리곤·경계 접근 감속·선회 행동은 없음.

## 3. 300 m 탐지 광학 타당성 분석 (R-3 · R-4 · R-5)

### 3.1 전제

- IMX568: 1/1.8" 글로벌 셔터, 5.1 MP **2472 × 2064**, 픽셀 2.74 µm, 유효 폭 6.77 mm.
- 렌즈 가정(발주 전 확정 필요): 광각 f≈6 mm → **HFOV ≈ 59°**, 협각 f≈25 mm → **HFOV ≈ 15.4°**. 상세 사양·배치(M12 통일, 네스티드 동축·수직 적층)·수락 기준은 **RIPOSTE-LENS-REQ-001**로 분리.
- 대상 각크기: 드론 0.35 m @300 m = **1.17 mrad**, 풍선 0.25 m @거리 d = 0.25/d rad.
- 검출 하한 가정: 학습을 소형 대상에 최적화해도 **bbox ≥ 8 px**(640×640 모델 입력 기준)은 있어야 80% 탐지율(R-6 기준)을 기대할 수 있다. 이 값은 모델 검증에서 갱신한다. [ASSUMPTION]

### 3.2 모드별 대상 픽셀 크기 (0.35 m 드론)

모델 입력 1 px가 담는 각도 = IFOV × (원본 px / 640).

| 카메라·모드 | 모델입력 1px 각도 | 300 m 대상 크기 | ≥8 px 되는 최대 거리 |
|---|---|---|---|
| 광각, 전체 프레임 640 리사이즈 | 1.64 mrad | **0.7 px** | ~27 m |
| 광각, 3×3 타일(824→640) | 0.55 mrad | **2.1 px** | ~80 m |
| 협각, 전체 프레임 640 리사이즈 | 0.42 mrad | 2.8 px | ~104 m |
| 협각, 3×3 타일(824→640) | 0.14 mrad | **8.3 px** | **~311 m** |

풍선(0.25 m)은 위 거리에 ×0.71: 광각 타일 ~57 m, 협각 타일 ~222 m.

### 3.3 결론 (핵심)

1. **R-3(300 m 탐지)은 협각 카메라 + 타일(또는 원본 해상도 ROI) 추론으로만 성립한다.** 광각은 3×3 타일을 써도 300 m에서 대상이 ~2 px라 물리적으로 불가.
2. 따라서 R-5의 "광각 우선 → 타일 → 협각" 순서는 **거리 대역별 역할 분담**으로 재해석해야 한다:
   - **원거리(~300 m) 최초 획득**: R-2의 GCS 큐(방향·거리)로 기체 헤딩/짐벌을 지향한 뒤 **협각 타일 탐색**이 주 수단.
   - **광각 640 리사이즈 패스**: 근거리(≤~30 m) 상시 감시·종말 유도·재획득용.
   - **광각 3×3 타일**: 중거리(≤~80 m) 탐색·트랙 소실 시 재획득용.
3. 협각 HFOV 15° @300 m의 지상 커버리지는 폭 ~81 m — GCS 큐의 방위 오차가 ±7° 이내여야 최초 획득이 한 번에 된다. 큐 정확도가 낮으면 협각 시야를 좌우로 훑는 **스캔 패턴**이 추가로 필요하다. [ASSUMPTION: GCS 큐 방위 정확도]
4. 렌즈 초점거리는 위 표의 민감 변수다. 협각을 35 mm(HFOV≈11°)로 하면 300 m에서 ~11.6 px로 여유가 생기지만 시야가 좁아져 큐 정확도 요구가 올라간다.

### 3.4 연산 예산 (Hailo-8)

- Hailo-8 (26 TOPS)에서 YOLOv8n/s 640×640은 수 ms/추론 — NPU 처리량(v8s ~100+ FPS)은 병목이 아니다. 병목은 **동기 detect() 파이프라인**: 60 fps 캡처(16.7 ms/frame) 기준 프레임당 1회 추론(RGA ~1.5 ms + v8s ~10 ms ≈ 12 ms)이 성립 한계이고, 프레임당 2회 추론은 비동기 파이프라이닝 없이는 불가 → R-10의 "프레임당 어느 채널 1개" 교차 배분이 이 제약에서 나온다.
- R-5의 "9개 타일 순차 탐색"은 채널당 30 Hz 추론(R-10 탐색 배분) 기준 **한 바퀴 0.3 s**. 8 m/s 접근 대상 기준 한 바퀴당 2.4 m 이동 — 탐색 단계에서는 허용 가능. Tracking 전환 후에는 대상 주변 타일만 추론해 지연을 줄인다.

### 3.5 광학·기구 배치안 (네스티드 동축 · 수직 적층)

렌즈 사양·조달 조건은 RIPOSTE-LENS-REQ-001로 분리했고, 배치 결정만 여기 기록한다.

- **배치: 네스티드 동축** — 협각 HFOV 15°가 광각 HFOV 59°의 중심에 오도록 광축 평행 정렬. 이 시스템은 감시가 아니라 **획득 깔때기**(광각 획득 → 협각 정밀 추적)이므로, 독립(광축 발산·커버리지 확장)과 부분 중첩 배치는 핸드오프에 기체 재지향이 필요해져 기각. 네스티드에서는 R-9 센터링 루프가 대상을 광각 중심에 가져다 놓으면 대상이 자동으로 협각 시야에 들어와, 핸드오프에 별도 기동이 없다. S-11 추론 배분과도 정합(TRACK 전환 시점에 대상이 이미 협각 시야 안).
- **수직 적층, 기선 ≤60 mm**(M12 기준 30–40 mm 목표): 기선을 수직축에 두면 시차 오프셋이 고도각 방향에만 생기고 **방위각은 두 채널이 일치** — PN 유도·yaw 센터링(R-9)의 임계 축을 시차에서 격리한다. 기선 50 mm의 시차: 300 m에서 0.17 mrad, 30 m에서 1.7 mrad — 해당 거리 대상 bbox 대비 무시 가능, 잔여는 §3.6 보정으로 흡수.
- **공통 강성 플레이트** 장착(진동·열변형 시 상대 정렬 유지), 기계 정렬 목표 ±0.5°, 잔차는 SW 보정(§3.6).
- **동기 캡처 필수**: IMX568 글로벌 셔터 + 외부 트리거(XVS)로 두 센서 동일 트리거 — 핸드오프 프레임에서 두 채널의 대상 위치가 같은 시각을 가리켜야 §3.6의 사상이 성립한다. RK3588 MIPI-CSI RX 2포트에 각 4-lane.

### 3.6 외부 파라미터 보정 절차 (광각↔협각 좌표 사상)

**사상 모델**: 왜곡 보정 후, 협각↔광각 정규화 좌표 사상은 **상수 각오프셋(Δaz, Δel) + 초점거리비 스케일**의 원거리 근사로 충분하다(광축 평행·기선 소·운용 거리 ≥30 m 전제). 시차는 수직 적층이라 고도각 성분만 남고, 필요 시 단안 거리 추정으로 δel = B/d 보정(30 m 미만은 광각 단독 구간이라 불필요).

- **공장 보정 절차**: ① ≥50 m 대상(또는 콜리메이터) 설치 → ② 동기 캡처로 양 채널 동시 촬영 → ③ 각 채널 대상 중심 픽셀 → 왜곡 보정 → 정규화 좌표 → ④ Δaz/Δel 산출, config 저장(`seeker.narrow_offset_az/el`) → ⑤ 3회 반복 측정 편차로 수락 판정.
- **수락 기준**: 사상 잔차 **≤0.1°** (협각 원본 ~16 px, 대상 ROI 대비 충분). 반복 편차 ≤0.05°.
- **비행 중 검증(연속 보정 감시)**: TRACK 중 R-7 광각 recheck 프레임은 두 채널이 같은 대상을 보는 유일한 정기 기회다 — 이때 사상 잔차를 블랙박스에 기록하고, 이동 평균이 수락 기준을 넘으면 HealthBus 경고(기구 변형·충격 이탈 감지). 재보정은 지상에서만 수행(비행 중 자동 갱신 금지 — 오추적을 보정값에 흡수하는 실패 모드 차단).
- **온도**: −20/+60 °C에서 오프셋 재측정 — 플레이트 열변형이 수락 기준 이내인지 확인(초과 시 온도별 보정 테이블이 아니라 기구 개선으로 대응).

> 배치(LENS-REQ §2.2)라 유효 기선(baseline)이 사실상 0이다. 따라서 R-11/R-12의

## 4. 탐지·추적 상태기계 설계안 (R-5 · R-6 · R-7)

시커 내부에 탐색 상태기계(SearchScheduler)를 신설한다.

```
CUE_SLEW      GCS 큐 방향으로 기체/카메라 지향 (OBC 협조, R-2)
   │ 지향 완료
SEARCH        [원거리] 협각 3×3 타일 순차 + 광각 640 패스 병행
   │ 검출 발생 (미확인)
CONFIRM       검출 영역 중심으로 광각·협각 협조 탐지.
   │          슬라이딩 윈도우: 최근 5프레임 중 ≥4프레임 동일 트랙 연관(R-6)
   │ 확인                      │ 5프레임 내 미달
TRACK  ◀──────┘               └──▶ SEARCH 복귀
   │  - 대상 중심 타일만 추론(광각·협각 중 대상 크기가 8~200px에 드는 채널 우선)
   │  - N프레임마다 전체 프레임 재탐지로 트랙-검출 일치 확인 (R-7, 기본 N=15)
   │  - TrackBus 발행 지속
   │ MAX_MISSES 초과 소실
REACQUIRE     마지막 예측 위치 주변 타일 → 광각 타일 전체 → SEARCH
```

- **CONFIRM 윈도우**: 현행 `MIN_TRACK_HITS`(연속 2회)를 **링버퍼 5프레임, 적중 ≥4** 로 교체한다. Tunables: `CONFIRM_WINDOW=5`, `CONFIRM_HITS=4`. 현행 파라미터보다 오검출 억제가 강해지고 R-6과 일치한다.
- **광각↔협각 핸드오프**: 두 채널의 외부 파라미터(장착 각 오프셋)를 보정해 정규화 좌표를 상호 사상한다. 트랙 ID는 채널 전환 시 유지하되 TargetEstimator는 채널별 HFOV/초점거리로 재구성한다(현행 Estimator는 단일 HFOV 고정 — 확장 필요). 핸드오프 프레임의 유한차분 속도는 리셋한다(SEEKER-SDD §6과 동일 원리: 기하 기준이 바뀐 프레임의 차분 금지).
- **타일 좌표 사상**: 타일 내 정규화 bbox → 전체 프레임 정규화 좌표로 환산 후 Tracker에 공급(Tracker/Estimator는 전 프레임 기준 좌표계 유지 — 기존 계약 불변).

### 4.1 적응형 추론 레이트 배분 (R-10)

**원칙: 캡처 레이트는 고정하고, 추론 스케줄을 적응시킨다.** 양 채널 모두 60 fps 캡처를 유지한 채, 어느 프레임에 어느 채널의 detect()를 돌릴지를 SearchScheduler가 상태별로 배분한다:

```
SEARCH/CONFIRM :  광각 30 Hz 추론(짝수 프레임) + 협각 30 Hz 추론(홀수 프레임)
TRACK 확정 후  :  협각 ~60 Hz 추론(전 프레임) + 광각 주기 재탐지(R-7)
                  광각 재탐지가 낀 프레임은 협각 1회 스킵(프레임당 추론 1회 유지, §3.4)
  └ 근거리(≤ narrow_boost_range_m, 기본 150 m)  :  광각 재탐지 주기를 늘려
     (track_recheck_period_near, 기본 90프레임) 협각을 사실상 60 Hz까지 상향
```

**근거리 협각 60 Hz 상향 (2026-08-16 구현, 항목 3)**: TRACK에서 협각은 이미 재탐지 슬롯을 제외한 전 프레임을 갖지만, 종말 단계(대상 ≤ 150 m)에서는 **광각 재탐지 주기를 `recheck_period`(기본 30) → `recheck_period_near`(기본 90)로 늘려** 협각이 사실상 60 Hz 추론에 도달한다. 범위는 TargetEstimator가 산출한 상대 거리(FRD 위치 크기)를 다음 프레임의 cue로 전달해 판정하며(1프레임 지연은 150 m 임계에 무의미), **거리 미상(추정 전)·boost 비활성(0)·대상 소실 시에는 상향하지 않는다**(오추정에 과도 반응 방지). 주기적 AI 재검증(R-7, 항목 2)은 폐지가 아니라 **드물게 유지** — 종말 정밀도와 검증 안전을 모두 지킨다. 세부는 SEEKER-SDD S-11. (임계는 SM-3 운용 반경 150 m와 정합 — 그 안에서는 커버리지보다 정밀도가 지배.)

**항목 대응 요약 (2026-08-16 사용자 운용개념 반영)**:
- **①** 광각 30 Hz + 협각 30 Hz 교차 추론(60 fps 캡처): R-10 SEARCH/CONFIRM 배분 — 구현 완료(SearchScheduler `channel()`).
- **②** 객체 인지 후 EO Tracking mode + 주기적 AI 검증: TRACK 모드 + R-7 주기 재탐지 — 구현 완료.
- **③** 근거리(≤150 m) 협각 60 Hz 상향: 위 문단 — **본 개정에서 신규 구현**.
- **④** Moving-target 예측(속도·방향): TargetEstimator(상대 속도) + TargetEkf(CV) + TargetImm(2-CA 혼합) 존재. **IMM의 production GuidanceSource 연결은 미완**(코드리뷰 P2-07) — 별도 항목으로 진행.

- **근거 1 (정밀도)**: 이득은 종말 단계에 집중된다 — 접근할수록 대상 각속도가 커지는데, 협각 60 Hz 추론은 LOS 각속도 추정 노이즈와 α-β 속도 추정·PN 명령 지연을 절반으로 줄인다. 탐색 단계는 시간 해상도가 아니라 커버리지가 지배하므로 30 Hz로 충분하다.
- **근거 2 (센서 모드 전환 금지)**: 대안인 "카메라 fps를 30→60으로 비행 중 전환"은 V4L2 스트림 정지→재협상→재시작으로 수백 ms 프레임 공백을 만든다. 하필 그 시점이 추적 확정 직후라, coast 한도(~267 ms) 안에 재시작하지 못하면 막 잡은 트랙을 전환 절차 때문에 잃는다. 추론 스케줄 방식은 같은 예산 재배분을 공백 0으로 달성하고, latest-wins 구조상 "건너뛴 프레임"은 이미 자연스러운 동작이다.
- **부수 이점**: 캡처가 항상 60 fps라 30 Hz 추론 구간에도 더 신선한 프레임을 잡는다(평균 프레임 나이 16.7→8 ms).
- **전환 트리거**: R-6 확인 윈도우(TRACK 진입/이탈)가 그대로 배분 전환 트리거다 — 별도 상태 불필요.
- **주의 1 (프레임 카운트 상수)**: 채널별 추론 레이트가 모드에 따라 30↔60 Hz로 바뀌므로, MAX_MISSES·CONFIRM_WINDOW 등 프레임 카운트 상수는 "캡처 프레임"이 아니라 **해당 채널의 추론 횟수** 기준으로 세거나 시간 기반으로 전환해야 시간 의미가 유지된다(구현 시 SEEKER-SDD Tunables 규칙과 함께 정리).
- **주의 2 (저조도 프로파일)**: 60 fps 고정 캡처는 노출 상한 ~16 ms를 강제한다. 야간 운용은 **이륙 전 결정**으로 캡처 자체를 30 fps 프로파일로 내리는 설정을 둔다(비행 중 전환은 여전히 금지).

### 4.2 광각 모션 후보 생성 (R-13)

광각 채널은 §3.3에서 "근거리 상시 감시·재획득용"으로 규정됐지만, 그 재획득은 지금까지 **탐지 모델에만** 의존했다. 모델이 없거나(현 상태) 대상이 학습 분포 밖이면 후보가 하나도 생기지 않는다. R-13은 **픽셀 운동만으로** 후보를 만드는 두 번째 경로다.

```
광각 프레임 t-1, t
      ↓ 특징점 추출(FAST) + 블록 정합 대응
전역 자기운동 추정 (RANSAC + 상사변환 4-DOF)
      ↓ 추정 변환으로 t-1을 t에 정렬
잔차 = |t - warp(t-1)|
      ↓ 임계 + 연결요소 그룹핑
소형 이동체 후보 (크기·조밀도 필터, 점수순)
```

- **자기운동 보상이 전제다**. 기체가 움직이는 동안 단순 차분은 화면 전체를 이동체로 만든다 — 배경을 먼저 정렬해야 잔차가 "배경 대비 독립적으로 움직인 것"이 된다.
- **모델은 상사변환(4-DOF: 회전·등방 스케일·평행이동)** 이다. 어핀(6-DOF)은 대응점이 한쪽에 몰리면 전단·비등방 스케일로 **실제 이동체까지 흡수**해 후보를 지운다. 공중 촬영의 지배적 자기운동은 회전+평행이동이고 스케일 변화는 작으므로 상사변환이 조건수와 강건성 모두에서 낫다.
- **RANSAC은 결정적**이다. 표본 추출에 고정 시드 LCG를 쓰므로 같은 입력이 같은 결과를 낸다 — 재현 불가능한 시험은 회귀 수단이 못 된다.
- **크기 상한이 오탐 억제의 핵심**이다. 시차(parallax)로 어긋나는 근경 구조물은 큰 덩어리로 남으므로, 소형 대상 크기 대역 밖의 blob은 버린다. 프레임 경계에 닿은 blob도 버린다(정렬 미정의 영역).
- 자기운동 추정은 **축소 영상**으로 충분하지만 잔차는 **원해상도**에서 본다 — 300 m 대상이 광각 원해상도에서 약 2~5 px(초점거리에 따라)이라 축소하면 사라진다. 처리율은 프레임률과 분리해 배분한다(§3 목표: 광각 모션 5~10 fps).
- 출력은 협각 타일 우선순위(R-15)와 재획득(R-16)의 입력이며, **그 자체로 트랙을 만들지 않는다** — 확정은 여전히 R-6 확인 윈도우가 담당한다(모션 후보는 "여기를 보라"이지 "대상이다"가 아니다).

**구현(2026-08-18, 순수 로직)**: `seeker/src/MotionCandidates.{h,cpp}` — OpenCV 불사용(S-9). 단위시험 `test/test_motion.cpp`(54 checks). 잔존은 파이프라인 배선(광각 슬롯에서의 호출 주기·스케줄러 연결)과 실기 튜닝.

**알고리즘 검증(2026-08-18)**: 수식을 손으로 재유도해 코드와 대조하고, 알려진 변환으로 합성한 장면에 대해 회복 오차를 실측했다. **결함 3건을 발견·수정**했다.

1. **정합이 정수 단위** — 블록 정합은 정수 변위만 내므로 추정이 디시메이션 격자에 양자화됐다(d=4에서 최대 2 px). 잔차 비교는 보간 강도를 쓰므로 이 정도 어긋남이 실제 이동체급 잔차를 만든다. SAD 비용면에 **포물선 서브픽셀 보정**을 넣어 오차를 2~4배 줄였다(640×480 평행이동 −0.54 → −0.14 px).
2. **회전·스케일에서 fail-closed가 성립하지 않았다** — 회전 변위는 고정점에서 멀수록 커져 탐색 반경을 넘는데, 중앙 대응점만으로 적합이 성립해 정합률 59%로 합의 문턱(50%)을 통과했다. 그 결과 **이동체가 전혀 없는 장면에서 후보 16건**이 나왔다(헤더가 문서화한 "범위를 넘으면 fail closed"와 정반대). **모델 예측 기반 유도 2차 정합**을 도입해 274/274 정합·오탐 0으로 해소했다.
3. **runner-up 판정이 스캔 순서에 의존** — 모호성 게이트가 그 시점의 잠정 승자를 기준으로 비교해 좋은 대응을 버리고 모호한 대응을 받아들일 수 있었다. 비용면 전체를 먼저 구한 뒤 2단계로 판정하도록 고쳤다.

부수적으로 **디시메이션 박스 중심 오프셋**(`t_full = d·t_dec + c(I−M)`, c=(d−1)/2)을 반영해 회전·스케일 케이스 오차를 추가로 20~40% 줄였고, 헤더가 "full-resolution"이라 명시하면서 실제로는 축소 좌표를 반환하던 단위 불일치를 바로잡았다(이제 전 구간 full-resolution).

**실측 특성**(합성 장면, 640×480 기준):

| 항목 | 측정값 |
|---|---|
| 검출 감도 | **상대 운동 1 px**부터 검출(점수 0.6~0.79). 상대 운동 0이면 후보 0 |
| 자기운동 회복 오차 | 평행이동 0.02~0.14 px, 회전+스케일 0.12~0.30 px |
| 회전 허용 한계 | ~6°/프레임까지 정상(60 Hz에서 360°/s — 실기 대비 매우 여유), ~10° 이상은 **fail closed**(적합 없음·후보 0) |
| 잡음 내성 | 진폭 10까지 오탐 없음. 진폭 20에서 오탐 발생 — `residual_threshold`는 프레임당 잡음 진폭의 **2배 이상**이어야 한다(브링업 튜닝 항목) |
| 반복 텍스처 | d=2에서는 정답(오차 0.06 px), d=4에서는 fail closed. 어느 쪽이든 **틀린 답을 자신 있게 내지 않는다** |

**본질적 한계(설계상, 결함 아님)**: 배경과 **같은 상대 운동**을 갖는 대상은 잔차가 없어 이 경로로는 보이지 않는다 — 정면 접근처럼 상대 화면 운동이 0인 기하가 그렇다. R-13은 탐지 모델을 **대체**하지 않고 보완한다. 시험으로 고정해 나중에 결함으로 오인되지 않게 했다.

### 4.3 탐색 강건화 (R-14 중첩 타일 · R-16 창 확장)

**중첩 타일 (R-14)**: 종전 타일 격자는 서로 맞닿아 있어 **이음매에 걸친 대상이 두 크롭으로 쪼개졌다** — 각 조각은 검출 하한(8 px) 아래로 떨어지고, 어쩌다 나온 박스는 잘려 있어 폭-정규화 크기가 작아지므로 **단안 거리 추정이 더 먼 대상으로 읽는다**. 타일링이 R-3(300 m)의 유일한 수단인데 그 이음매가 사각지대였다.

- 각 타일을 `tile_overlap`(기본 0.12)만큼 키우고, 첫 타일이 0에서 시작해 마지막이 1에서 끝나도록 균등 배치한다. 이웃이 겹치면서 합집합은 여전히 프레임 전체를 정확히 덮는다.
- **overlap=0이면 종전 격자와 완전히 동일**(x=col/g, w=1/g)하다 — 기존 동작이 특수 케이스로 포함되므로 별도 분기가 없다.
- 검증은 "타일이 겹친다"가 아니라 그 **결과**를 고정한다: 0.03 크기 대상의 중심을 201×201 격자로 훑어 **모든 위치에서 어느 한 타일 안에 온전히 들어가는지** 확인한다(중첩 제거 시 즉시 실패).

**창 확장 (R-16)**: TRACK/CONFIRM의 큐 창은 트래커의 **예측 위치**에 중심을 두는데, 그 예측은 검출이 없는 동안 바로 드리프트한다. 종전에는 창 크기가 고정이라, 놓치기 시작한 대상을 **가장 있을 법하지 않은 자리**에서 계속 찾았다.

- 연속 미검출마다 창을 `track_roi_growth`(기본 1.25)배로 넓히고 `track_roi_max`(기본 0.60)에서 멈춘다. 검출 1회로 즉시 원래 크기로 복귀한다.
- **확장은 공짜가 아니다**: 창이 넓어지면 대상이 모델 입력에서 차지하는 픽셀이 줄어 검출이 오히려 어려워진다. 그래서 전체 프레임까지 열지 않고 상한을 둔다 — 해상도가 가장 필요한 순간에 해상도를 버리는 일을 막는다.
- `track_roi_growth=1`이면 종전 고정 창 동작과 완전히 동일하다.
- **TRACK 이탈 조건은 바꾸지 않았다**. "짧은 미검출은 트래커가 이미 coast하므로 트랙 폐기 시에만 탐색으로 복귀"(§4.2)는 churn 방지를 위한 기존 결정이고, 창을 넓히는 것은 재검출 확률을 올리기만 할 뿐 그 결정과 무관하다.

설정 키(`[seeker]`): `tile_overlap` [0,1), `track_roi_growth` ≥1, `track_roi_max` ∈ [track_roi_min, 1] — 모두 기동 시 범위 검증한다. 상한이 하한보다 작은 조합은 "확장을 설정했으나 무효"인 무음 no-op이라 거부한다.

## 5. 다중대상 정책 (R-8)

- primary 선정 기준을 **quality → 폭-정규화 size(겉보기 크기 = 최근접 근사)** 로 교체. 동률 시 quality. sticky 유지(세션 활성 중 가로채기 방지, S-3 계승) — 즉 "최초 확정 시 최대 크기 우선, 이후 고정, 소멸 시 잔존 최대 크기로 핸드오프".
- **확정 전(pre-lock) 재선정 히스테리시스 (2026-08-18 코드리뷰 반영)**: 확정 전 매 프레임 재선정은 유지하되, 살아 있는 현직은 도전자의 평활 크기가 `TRACKER_PRIMARY_SWITCH_MARGIN`(1.2배)을 넘을 때만 교체된다. 마진이 없으면 크기가 비슷한 두 대상이 박스 노이즈로 순위를 매 프레임 뒤집고, 뒤집힐 때마다 확인 윈도우가 정체성 결합(TR-7) 규칙대로 0으로 리셋되어 **두 대상이 모두 살아 있는 동안 확인이 영원히 끝나지 않는다**(발행 불능 라이브락). 진짜 접근하는 대상은 크기가 1/거리로 자라 마진을 금방 넘으므로 R-8("가장 가까운 위협 먼저")은 유지된다. 상세는 SEEKER-SDD §5 S-3.
- **대상 개수 저장**: `TrackState`에 `num_tracks`(확정 트랙 수) 필드 추가. shm 계약 변경이므로 구조체 말미 append + `pad` 재배치, 리더/라이터 동시 배포. Recorder/Blackbox에도 기록.
- 현행 `TRACKER_MAX_TRACKS=8` 초과 대상은 무시되어 개수가 8에서 포화 — 시험(T-3)에서 풍선 수가 이를 넘지 않게 하거나 상한을 조정.

## 6. GCS 큐 인터셉트 및 중심 유지 비행 (R-1 · R-2 · R-9)

- **R-1/R-2 (부분 존재, 단 현재 동작 불능)**: `ObcCommand::TARGET`(NED 좌표+헤딩) → `MissionSource`(TAKEOFF→TRANSIT_TO_CUE→시커 획득 시 SEEKER_APPROACH 핸드오버) 골격이 이미 있다. 그러나:
  - **차단 결함 2건은 수정 완료**(§8.1): TARGET 명령 인증 거부(F-1), 미션 이륙이 SM-3 고도 하한에 걸리는 문제(F-2). 이로써 GCS 큐 → 이륙 → 큐 지점 항법 → 시커 핸드오버 경로가 실제로 동작한다.
  - 확장 항목: ① 큐 페이로드에 **대상 속도 벡터** 추가(현재 위치+헤딩뿐 → 접근점 예측 불가), ② 좌표 형식 — 현재는 로컬 EKF NED 절대좌표라 GCS가 원점을 알기 어려움 → **lat/lon 또는 자기체 상대 방위/거리** 입력 경로 신설, ③ 예상 접근점 `P_int = P_tgt + V_tgt × t_go` 반복 산출, ④ 큐 도달(협각 획득 거리 ~300 m) 시 시커 SEARCH 전환 트리거, ⑤ **SM-8 타임박스(60 s)·SM-3 반경(150 m) 기본값이 300 m 왕복 시나리오와 기하학적으로 충돌** — 미션 프로파일별 재설정.
- **R-9 (수직 센터링 구현, 2026-08-15)**: `AttitudeTrackingSource`의 pitch를 고정
  −15°에서 **대상 LOS 고도각 추종 + 추종 바이어스**로 교체했다:
  `pitch = −atan2(down, horiz) − track_pitch_deg`. yaw는 종전대로 방위 지향
  (수평 센터링). 짐벌 없는 body-fixed 카메라에서 자세가 곧 지향 명령이므로,
  이로써 대상이 위/아래로 움직여도 pitch가 추종해 **수직 시야 이탈(S-G4)** 이
  해소된다. rel_pos_frd에서 각오차를 복원하므로 TrackState 필드 확장은 불필요.
  단위시험 `test_attitude` +2(대상 위→nose up 추종, 아래→nose down). 게인
  (`track_pitch_deg`)은 flight-tune. SM-4 자세 클램프는 종전대로 상위에서
  적용. 수용 기준(TRACK 중 |cx−0.5|<0.15, |cy−0.5|<0.15)의 실측 검증은 SITL/
  비행 항목. 남은 것: 픽셀 오차 비례 게인 튜닝(현재는 LOS 각도 직접 지향).

## 7. 풍선 시험 SW 설계안 (T-1 ~ T-5)

### 7.1 대상 설정

- 탐지 모델에 풍선 클래스 추가(또는 시험 전용 HEF). config: `seeker.target_class`, `seeker.target_size_m=0.25`. 현행 코드의 `cls==0` 하드코딩(Tracker 후보 필터, 오버레이 best_detection)을 config 주입으로 교체.
- 협각 없이 광각만 쓸 경우 풍선 유효 탐지 거리 ~57 m(타일) — 50×50 m 지오펜스 내 운용에 충분. **시험 SW는 광각 단독으로 성립**하며, 협각 협조는 운용 기능 검증 항목으로 분리 가능.

### 7.2 지오펜스 (T-1)

- 신규 SM 항목 **SM-10 폴리곤 지오펜스**: GPS 좌표 꼭짓점 목록(기본 50×50 m 사각형)을 config로 로드, 로컬 NED로 변환 후 점-내부 판정.
- 이중 경계 구조:
  - **소프트 마진**(경계 −10 m부터): 접근 속도 성분을 거리 비례로 감속(T-5) — 유도 출력 스케일링, SafetyMonitor가 아닌 행동 계층에서 수행.
  - **하드 경계**: 침범 시 기존 SM-3와 동일하게 disengage → 안전측 정지. PX4 자체 지오펜스(GF_*)를 최종 방벽으로 병행 설정.

### 7.3 순찰 행동 (T-4 · T-5)

신설 `BalloonPatrolSource`(ISetpointSource 구현, 시험 빌드 전용):

```
SEARCH_TURN   제자리 저속 yaw 선회 + 시커 SEARCH — 풍선 확정(R-6 윈도우) 대기
   │ 확정
APPROACH      PN/직진 유도로 풍선 접근 (SM-4 클램프 유지)
   │ 펜스 소프트 마진 진입           │ 풍선 도달(range < R_hit) 또는 트랙 소실
SLOW_TURN     감속 → 펜스 내측으로 선회 ──▶ 현재 트랙 폐기 → SEARCH_TURN
```

- "도달" 판정: 단안 거리 추정 `range < 3 m` 또는 bbox 크기 임계 초과 (풍선 크기 25 cm 고정이므로 단안 거리 신뢰 가능 — 오히려 드론보다 조건이 좋음).
- 이미 대응한 풍선 재선정 방지: 도달 후 해당 방위 ±θ를 일정 시간 탐색 제외(쿨다운 목록).
- 운용 안전 요건 유지: 시험 모드에서도 OperatorAuthorization(engage 토큰)·SM 전 항목·배터리 게이트는 동일 적용. 자동 재-engage는 두지 않고 1회 engage로 순찰 지속, disengage로 종료.
