# LTE auto-rate 운용 가이드 (SAN v1.3 PHASE 5b)

> Source: SAN-SDD-SUR-001 v1.3 §6 (영상), §5.5 (LTE), TST §S15-5

PHASE 5 머지 시점에 보류로 남았던 "LTE 신호 변동 시 자동 bitrate 조정"
요구사항 구현분. Hub UGV SBC #2의 `gstreamer_relay_node`가 1 Hz로
publish 되는 `/lte/link_quality` 의 RSRP grade 를 보고 active stream
들의 quality 를 hysteresis 로 조정합니다.

## 1. 데이터 흐름

```
ModemManager (D-Bus) ─poll──▶ /var/run/san/lte_link_quality (key=value)
                                          │
                                          ▼
                              lte_link_quality_node (1 Hz publish)
                                          │
                                          ▼
                                 /lte/link_quality (RSRP/RSRQ/grade)
                                          │
                                          ▼
                       AutoRateController (hysteresis FSM)
                                          │ apply callback
                                          ▼
                       GStreamerRelayNode active streams
                       └ pipeline rebuild w/ new bitrate
```

ROS2 프로세스는 ModemManager 와 modem lock 을 다투지 않기 위해
**파일 read-only 만** 합니다. status 파일을 채워주는 폴러(qmicli /
mmcli / pymobile-broadband) 는 외부 systemd 유닛으로 별도 배포합니다.

## 2. status 파일 포맷

`/var/run/san/lte_link_quality` — 한 줄에 `key=value`. 알 수 없는 키는
조용히 무시. 예시:

```
# auto-generated by modemmanager-poller.service
rsrp_dbm=-95
rsrq_db=-10
sinr_db=14
```

- `rsrp_dbm` (필수): 없거나 비숫자면 `LTE_GRADE_UNKNOWN` 으로 처리되어
  controller 는 아무 동작도 하지 않습니다.
- `rsrq_db`, `sinr_db` (선택): 진단용. 현재 grade 결정은 RSRP 단독 입니다.
- 파싱 시 `rsrp_dbm` 은 `[-140, 0]`, `rsrq_db` 는 `[-20, 0]`,
  `sinr_db` 는 `[-30, 40]` 범위로 clamp.

## 3. RSRP → grade → quality 매핑

| RSRP (dBm) | grade | 영상 quality (ceiling 무제한) | 비트레이트 (kbps) |
|---|---|---|---|
| `>= -85` | EXCELLENT | FHD | 4000 |
| `-100 ~ -86` | GOOD | HD | 1500 |
| `-110 ~ -101` | FAIR | LOW | 500 |
| `<= -111` | POOR | THUMBNAIL | 100 |
| (UNKNOWN) | UNKNOWN | (무동작) | — |

ceiling (`Config::ceiling_quality`) 을 낮추면 EXCELLENT 에서도 그 값
이상으로 올라가지 않습니다. 기본값 FHD.

## 4. Hysteresis 정책

- **demote** (신호 악화): 1 sample 즉시 적용. 대역 saturation 을
  방지해야 하므로 hysteresis 없음.
- **promote** (신호 호전): 연속 `promote_hold_ticks` (기본 5) tick
  동안 같은 better-grade 가 유지되어야 적용. 1 sample 글리치를 흡수.

`UNKNOWN` 샘플은 controller 의 pending promotion 카운터를 0 으로
리셋하며 어느 방향으로도 움직이지 않습니다.

## 5. 동시 stream 4+ 시의 우선순위

`GStreamerRelayNode::downgradeAllToThumbnail()` (PHASE 5) 가 호출되면
`auto_rate_->setExternalThumbnailLock(true)` 가 함께 set 되어
**concurrency-driven thumbnail 이 link-quality-driven policy 보다 우선**
합니다. 잠금 동안 controller 는 grade 를 계속 tracking 하지만 applier
는 호출하지 않습니다. active 가 4 미만으로 떨어지면 lock 이 해제되며
다음 sample 부터 정상 동작합니다.

## 6. ROS2 파라미터

### `san_lte_redundancy/lte_link_quality_node`

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `status_file_path` | `/var/run/san/lte_link_quality` | key=value status file path |
| `source_iface` | `lte0` | header.frame_id + msg.source_iface 에 박힘 |
| `publish_period_ms` | 1000 | 1 Hz cadence |

### `san_hub_comm/gstreamer_relay_node` (신규)

| 파라미터 | 기본값 | 설명 |
|---|---|---|
| `auto_rate_enabled` | true | false 면 LTE 토픽 구독 안함 (manual CHANGE_QUALITY only) |
| `auto_rate_promote_hold_ticks` | 5 | promote 시 hold ticks |

## 7. 검증

```bash
# 1) status 파일 갱신 모의
echo -e "rsrp_dbm=-95\nrsrq_db=-10\nsinr_db=15" \
    | sudo tee /var/run/san/lte_link_quality

# 2) link_quality 토픽 확인 (1 Hz)
ros2 topic echo /lte/link_quality

# 3) relay 로그에서 auto-rate 적용 메시지 확인
docker logs -f san_hub_comm 2>&1 | grep auto-rate
```

S15-5 시나리오에서는 차량 이동에 따라 RSRP 가 -85 → -105 → -115 로
스윕 되며 EXCELLENT → FAIR → POOR 전이가 발생하고, relay 로그에
다음과 같은 라인이 차례로 찍혀야 합니다:

```
[INFO] auto-rate: applied target_quality=2 to N streams   (HD)
[INFO] auto-rate: applied target_quality=1 to N streams   (LOW)
[INFO] auto-rate: applied target_quality=0 to N streams   (THUMBNAIL)
```

복귀 시 hold 5 tick 후 promote 가 일어나므로 로그 간 간격이
demote 대비 길게 (~5 s) 보이는 것이 정상입니다.
